qing 项目 AI 辅助开发上下文
一、项目概述
qing 是一款基于 Next.js 16 + React 19 + TypeScript 的练琴辅助应用，核心功能包括：

使用 OpenSheetMusicDisplay (OSMD) 渲染 MusicXML 乐谱

提供虚拟键盘高亮当前演奏音符

通过 Web Audio 发出钢琴音色（MIDI 映射）

支持速度调节、A-B 循环、进度显示、自动滚动

当前项目代码位于：https://github.com/yuguogang/qing

二、核心设计理念（我们必须遵循的架构原则）
经过前期调研和实验验证，我们确立了以下设计原则，所有重构和新增代码必须遵循：

1. Cursor 是唯一的真相源（Single Source of Truth）
所有播放状态（当前音符、小节号、时间）只从 osmd.cursor.Iterator 读取。

禁止在应用层维护重复的位置状态（如 currentStep、currentMeasure 等）。

2. 事件驱动（Event-Driven）
模块间通信必须通过 EventBus（位于 src/lib/event-bus.ts）进行。

生产方（如播放引擎）在状态变化时 emit 事件。

消费方（如虚拟键盘、进度条、乐谱视图）通过 on 订阅事件，禁止主动轮询。

3. 移除预扫描（No Pre-scanning）
乐谱加载后不应遍历全曲构建时间表（cursorSchedule）。

利用 OSMD 内部 CurrentEnrolledTimestamp 作为播放时间基准，实现即加载即播放。

4. 帧驱动（Frame-Driven）
播放循环必须使用 requestAnimationFrame，禁止使用 setInterval 或 setTimeout 驱动主循环。

使用 performance.now() 计算 deltaTime 实现精确时间步进。

5. 模块解耦（Decoupling）
UI 组件（ScoreViewer、VirtualKeyboard）不应直接依赖 PracticeController 的具体实现，仅通过 EventBus 订阅事件。

音频引擎应独立为 MidiScheduler，通过事件接收音符并提前调度（look-ahead）。

模块说明
PlaybackEngine（替代 PracticeController）：

维护 elapsedTime（秒，与 CurrentEnrolledTimestamp 对齐）

使用 requestAnimationFrame 推进时间

调用 CursorDriver 推进光标

检测 A-B 循环边界

广播 position-changed 事件

CursorDriver（封装 OSMD cursor）：

提供 advanceTo(targetTime) 方法，循环调用 cursor.next() 直至 CurrentEnrolledTimestamp >= targetTime

每次 next() 后提取事件数据并交给 PlaybackEngine 广播

MidiScheduler（替代 PianoAudioEngine 的实时触发）：

订阅 position-changed 事件

维护一个调度队列，根据 enrolledTime 提前 500ms 将音符调度到 Web Audio（使用 Tone.Transport 或 AudioContext 精确时间）

停止时清空所有待调度事件

UI 组件：

VirtualKeyboard：订阅事件，高亮对应琴键

ScoreViewer：订阅事件，更新进度条、小节号、自动滚动

五、关键 API 和数据结构定义
EventBus 事件定义（需扩展 src/lib/event-bus.ts）
typescript
// 扩展事件类型
export type EventPayload = {
  // 已有
  'cursor:step': { step: number; totalSteps: number };
  'note:start': { midi: number; duration: number; velocity: number };
  // 新增 —— 核心事件
  'position-changed': {
    enrolledTime: number;        // 从 cursor.Iterator.CurrentEnrolledTimestamp 读取
    sourceTimestamp: number;     // 从 cursor.Iterator.CurrentSourceTimestamp 读取
    notes: Array<{ midi: number; pitch: string; duration: number }>;
    measureNumber: number;
    stepIndex: number;           // 当前步进序号（从0开始）
    totalSteps: number;          // 总步数（可通过预扫描获取，或设为 -1）
    progress: number;            // 0~1 的进度（enrolledTime / totalDuration）
  };
  'playback:state': { state: 'playing' | 'paused' | 'stopped' };
  'loop:boundary': { loopStart: number; loopEnd: number };
};

OSMD 关键属性（读取位置）
osmd.cursor.Iterator.CurrentEnrolledTimestamp：播放时间线（单调递增，自动处理重复），单位与 MusicXML 的 duration 相关，通常为秒。

osmd.cursor.Iterator.CurrentSourceTimestamp：原始乐谱时间（遇到重复会回跳）。

osmd.cursor.Iterator.CurrentVoiceEntries：当前光标下的所有声部条目数组。

osmd.cursor.Iterator.CurrentMeasure：当前小节对象。

osmd.cursor.Iterator.EndReached：是否到达乐曲末尾。

重要：CurrentEnrolledTimestamp 是同步 MIDI 和 UI 的唯一时间基准。所有时间计算都基于它。

六、改造步骤（分阶段实施）
Phase 1：扩展 EventBus 并定义 position-changed 事件
更新 src/lib/event-bus.ts，添加新事件类型。

在 PracticeController 中临时使用 eventBus.emit('position-changed', ...) 测试事件广播。

Phase 2：重构 PracticeController → PlaybackEngine
移除 cursorSchedule 和 buildCursorSchedule。

将 setInterval 替换为 requestAnimationFrame。

实现 advanceCursorTo 方法，使用 while 循环推进 cursor.next()。

在每次 next() 后广播 position-changed。

实现 seekTo、setLoop 等新方法。

Phase 3：改造音频引擎为 MidiScheduler
保留 PianoAudioEngine 作为底层音源，但移除其中的 setTimeout 触发。

在 MidiScheduler 中订阅 position-changed，将音符按 enrolledTime 调度到 Web Audio 时间线（使用 Tone.Transport 或 AudioContext 的 currentTime）。

实现 look-ahead 策略（提前 500ms 调度）。

Phase 4：UI 组件改为事件订阅
ScoreViewer：移除 setInterval，在 useEffect 中订阅 position-changed，更新进度、小节号、滚动。

VirtualKeyboard：订阅 position-changed，更新高亮琴键。

移除组件间通过 props 传递 currentStep、activeNotes 的方式。

Phase 5：集成测试与优化
测试带 repeat/D.S./D.C. 的乐谱，验证 cursor 自动回跳和事件广播。

测试变速、A-B 循环、seek 跳转。

性能优化：避免在 position-changed 中频繁重绘（使用 React.memo、useMemo 等）。

七、代码规范
TypeScript 严格模式：启用 strict: true，避免使用 any。

React 函数组件：使用函数组件 + Hooks，禁止类组件。

样式：使用 Tailwind CSS，遵循项目现有样式约定。

导入顺序：第三方库 > 内部模块 > 相对路径。

命名：

文件名：kebab-case（如 playback-engine.ts）

组件名：PascalCase（如 ScoreViewer）

变量/函数：camelCase

常量：UPPER_SNAKE_CASE

注释：为公共 API 和复杂逻辑添加 JSDoc 注释。

八、注意事项
OSMD 版本：当前项目使用 opensheetmusicdisplay@^2.1.0，API 稳定。

reset 方法：如果 cursor.reset() 不存在，可通过重新创建 MusicPartManagerIterator 实现。

总时长 totalDuration：由于移除了预扫描，可考虑在首次加载时快速预扫描仅获取总时长（不保存时间表），或者动态计算（在推进过程中累加）。推荐在 PlaybackEngine 初始化时通过一个轻量级预扫描获取总时长，但不保存每一步的细节。

性能：position-changed 事件触发频率可能很高（每次音符），需确保订阅者的处理函数轻量，避免阻塞主线程。

A-B 循环与 seekTo：在 seekTo 时，需要重置 elapsedTime 并快进 cursor，注意快进过程中要跳过音频调度（静默模式），避免产生杂音。

九、对 AI 的提示
在生成代码时，请遵循上述设计原则和架构规范。如果需要修改现有文件，请优先保持向后兼容（例如先扩展接口，再逐步迁移）。生成代码后，请附带必要的说明和用法示例。

最终目标：打造一个流畅、同步、可扩展的练琴应用，充分利用 OSMD 内置的重复处理能力，通过事件驱动实现高度模块化。
